# 튜토리얼 핵심 흐름 스모크 체크리스트

## 1. 사용 목적

이 체크리스트는 `TutorialScene` 분리 전후의 눈에 보이는 동작을 같은 순서로 확인한다.
분리 작업은 전투 규칙이나 레이아웃을 바꾸지 않으므로, 아래 기대 결과가 기준 커밋
`253507b`와 동일해야 한다.

## 2. 자동 기준선

| 검사 | 분리 전 | Turn 03 지시 전 확인 |
| --- | --- | --- |
| 모델 테스트 | 14개 통과 | 14개 통과 |
| Undo/재시작 소스 계약 | 2개 통과 | 2개 통과 |
| scene seam 계약 | 없음 | 7개 통과 |
| 저장소 검사 | 오류 0, 예정된 에셋 경고 5 | 오류 0, 같은 경고 5 |

위 결과는 사용자의 별도 테스트 중단 요청 전에 수집했다. 요청 이후에는 테스트를 다시
실행하지 않았다.

## 3. 런타임 수동 확인

Turn 03에서는 일반 브라우저로 모든 모듈이 로드되는 것까지 확인했지만,
`nw_bridge.js`가 요구하는 NW.js 런타임은 브라우저에서 제공되지 않았다. 포함된 NW.js 앱의
화면 자동화는 Codexpal 상태가 `disallowed`여서 수행하지 않았다. 따라서 아래 항목은 회귀
없음을 주장하지 않고 모두 명시적으로 미확인 상태로 남긴다.

Turn 05에서도 사용자의 별도 테스트 중단 요청에 따라 자동 테스트와 수동 런타임 확인을
실행하지 않았다. 따라서 전투 뷰 분리 뒤에도 S01~S18은 모두 미확인 상태이며, 정적 구조
검사 결과만 별도로 기록한다.

Turn 06 역시 같은 요청을 적용해 테스트 명령과 NW.js 수동 확인을 실행하지 않았다.
프레젠터 cue, 피드백 수명, 겹친 애니메이션 잠금과 에셋 loader 성공·실패를 다루는 테스트
소스는 추가했지만 미실행 상태다. 특히 S06·S08·S10~S13·S17의 연출 완료 후 입력 잠금과
명령 큐 진행은 런타임에서 확인해야 한다.

Turn 07에서는 전투 공통 규칙, 로라 의도, 플레이어 행동 미리보기를 각각 독립 클래스로
분리했다. 미리보기와 실제 행동의 동등성 테스트 소스는 추가했지만 같은 요청에 따라 실행하지
않았다. 따라서 아래 S08~S11의 수치·턴 전환과 새 미리보기 계약은 모두 런타임 미확인이다.

Turn 08에서는 다음 로라 행동, 플레이어 행동 전후 수치, pending HP 구간, 아이템 조사와
첫 플레이 안내를 각각 분리된 표시·포커스·안내 클래스로 연결했다. 테스트와 NW.js 실행은
같은 요청에 따라 수행하지 않았으므로 좁은 화면의 실제 줄바꿈, 마우스/키보드 포커스 동등성,
첫 플레이 메타 이관과 모든 연출 cue는 런타임 미확인이다.

Turn 09에서는 아이템과 이벤트 타일 수치를 선언형 effect executor로 이관했다. effect 계약과
preview/apply 동등성 테스트 소스는 추가했지만 사용자 요청에 따라 실행하지 않았다. 따라서
S05·S08·S10·S11의 실제 수치와 event 순서가 리팩터링 전과 같은지는 런타임 미확인이다.

### Turn 06 잠금 집중 확인

- 행동 pulse와 HP/불안정도 gauge 보간이 겹쳐도 행동 pulse 완료 뒤 입력이 정상적으로 열린다.
- 경로 이동 또는 텔레포트가 끝나기 전에 다음 전투 명령이 적용되지 않는다.
- 층 fade와 다른 연출이 겹치면 모든 잠금 연출이 끝난 뒤 한 번만 입력이 열린다.
- 재시작, 메뉴 복귀, 장면 파괴 중 애니메이션 Promise가 늦게 완료돼도 새 런을 잠그거나
  이전 좌표·층으로 되돌리지 않는다.
- 이미지 로드 실패 시 초상화·스프라이트·아이콘이 null 폴백으로 빠지고 입력과 결과 흐름은
  계속 진행된다.

### Turn 07 전투 미리보기 집중 확인

- 미리보기를 반복 호출해도 HP, 불안정도, 인벤토리, 사용 아이템과 체크포인트가 바뀌지 않는다.
- 활·인형탈·낡은 곰인형·오르골·버섯을 적용한 예상 수치가 실제 행동 직후 값과 같다.
- 로라의 다섯 불안정 상태에서 의도 상태, 근접/전역 범위와 실제 행동이 일치한다.
- 평화, 잘못된 단계·대상·아이템에서 버튼 설명용 reason ID와 실제 실패 reason이 같다.
- 헤이스트와 거울이 있는 행동에서 남은 행동, 보너스 턴, 다음 단계 예측이 실제 전환과 같다.

### Turn 08 전투 가독성 집중 확인

- 플레이어 턴에는 `현재 기준` 다음 로라 행동·상태·최종 피해·근접/전체 범위·사유가 보인다.
- 공격, 회복, 아이템, 대기 선택을 바꾸면 로라 HP·내 HP·불안정도의 현재→예상 값과 pending
  게이지 구간이 같은 프레임에 바뀐다.
- 피해 `-N`, 회복 `+N`, 불안정도 `+N/-N`, 무효와 무공격 문구가 해당 액터 위에 짧게 뜬다.
- 아이템 설명은 해당 버튼을 마우스로 가리키거나 `Tab`으로 포커스했을 때만 표시되며 두
  입력의 문구가 같다.
- 첫 플레이에서 세 개의 확정 문구가 자동 표시되고 닫을 수 있다. 다시 시작한 플레이에서는
  강제 표시되지 않으며 `H` 또는 도움 버튼으로 다시 연다.
- 1280×640 최소 높이와 와이드 화면에서 안내 모달, 다음 행동 패널, 아이템 설명이 잘리거나
  다른 HUD 버튼과 겹치지 않는다.

### Turn 09 선언형 효과 집중 확인

- 활·곰인형·버섯을 함께 적용한 공격이 원거리 원시 피해→고정 감산→배율 순서로 계산된다.
- 인형탈과 낡은 곰인형의 피해 감소, 오카리나의 양수 불안정도 억제가 실제 event 값과 같다.
- 오르골을 소비한 뒤에도 남은 평화 턴 동안 안정 효과가 유지되고 공격이 발생하지 않는다.
- 버섯을 소비한 뒤 이동·공격 배율이 유지되며 실제 양수 피해를 받은 순간에만 종료된다.
- 피해, 이동력 감소, 불안정도 증감 이벤트 타일이 반복 진입마다 기존 event 타입·순서로 동작한다.
- 타일 정화제가 negative 타일만 `instability-down`으로 바꾸고 이동·행동 자원을 소비하지 않는다.

## 4. 회귀 발생 시 경계 찾기

- 모드·버튼 노출 오류: `_tutorial_mode_policy.js`와 비전투 view의 button spec을 확인한다.
- 키 누락·중복: `_tutorial_input_bindings.js`와 scene seam 테스트를 확인한다.
- 좌표·경로 표시 오류: `_tutorial_value_utils.js`, battle layout과 모델 `previewPath()`를 구분해 확인한다.
- 상태는 맞고 연출만 다른 경우: presenter cue와 feedback queue를 확인한다.
- 연출 완료 뒤 입력이 너무 일찍 열리거나 계속 잠긴 경우: animation timeline의 세대와
  활성 잠금 토큰을 확인한다.
- 이미지 누락·정리 문제: asset loader readiness와 `destroy()`를 확인한다.
- 전투 수치가 달라진 경우: 뷰에서 재계산하지 않았는지 확인하고 모델 테스트를 우선 실행한다.
- 아이템·이벤트 효과가 다른 경우: `ITEMS[*].effects`, `EVENT_TILE_EFFECTS`와
  `TutorialEffectRegistry`의 검증·원본 순서, `TutorialEffectExecutor`의 조건·order를 확인한다.
- 전투 미리보기만 다른 경우: 공통 combat rules를 우회하는 계산이 생겼는지 확인하고
  로라 intent planner와 player action previewer의 입력 상태를 비교한다.

수동 실행 결과에는 실행 해상도, 선택 스타터, 처음 실패한 ID와 화면 캡처 또는 재현 순서를
함께 기록한다. 자동 테스트 통과만으로 전체 UI 동등성을 주장하지 않는다.
