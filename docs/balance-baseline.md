# 튜토리얼 밸런스 시뮬레이션 기준선

## 목적과 현재 상태

`TutorialBattleModel`의 실제 공개 API를 이용해 스타터와 플레이 성향에 따른
튜토리얼 결과를 반복 가능하게 비교한다. 게임의 밸런스 데이터는 이 하네스에서
변경하지 않는다.

2026-08-28 기준으로 하네스와 회귀 테스트 소스는 작성했지만, 사용자의 별도
테스트 일시 중단 지시에 따라 시뮬레이션과 테스트를 실행하지 않았다. 따라서
완료율, 엔딩 분포, 피해량 같은 측정 수치는 아직 기준값으로 확정하지 않았으며
임의의 수치를 기입하지 않는다.

| 기준 항목 | 현재 값 |
| --- | --- |
| 대상 조합 | 스타터 2종 × agent 4종 = 8개 시나리오 |
| 모델 변경 명령 상한 | 시나리오당 256회 |
| 난수 | 사용하지 않음, seed는 `null` |
| 실행 결과 기준선 | 측정 보류 |
| 테스트 결과 기준선 | 실행 보류 |
| 생성 JSON | `reports/tutorial-balance-report.json` (Git 제외) |

## 설명 가능한 agent 규칙

### 활 공격 우선 (`bow-attack-first`)

1. 활을 보유하면 제자리 이동 뒤 로라 원거리 공격을 우선한다.
2. 활이 없으면 이번 턴의 공개 도달 후보 가운데 로라에 가까운 안전한 타일로 간다.
3. HP가 25% 이하일 때만 회복을 공격보다 앞세운다.

### 인형탈 안정화 우선 (`mascot-stability-first`)

1. 오카리나, 오르골, 낡은 곰인형, 아이라인, 사진과 positive 이벤트에 접근한다.
2. 사용 가능한 안정 아이템을 공격보다 먼저 사용한다.
3. HP가 55% 이하이면 회복하고, 안정 수단이 없을 때 근접 우선으로 로라를 공격한다.

### 아이템 수집·상호작용 우선 (`item-interaction-first`)

1. 미획득 아이템을 통과하거나 가까워지는 경로를 먼저 고른다.
2. 수집 대상이 없으면 정화제 드롭을 위해 몹에 접근하고 로라보다 몹을 먼저 공격한다.
3. 사용 가능한 아이템과 negative 이벤트 타일 정화를 가능한 즉시 수행한다.

### 대기·회복 남용 탐지 (`naive-recovery-abuse`)

1. 항상 제자리 이동을 확정한다.
2. HP와 무관하게 회복하고, 회복 preview가 거부될 때만 대기한다.
3. 공격과 아이템 사용을 하지 않아 회복·대기만으로 진행을 우회할 수 있는지 드러낸다.

## 결정론 규약

- 모델과 agent는 난수를 사용하지 않는다.
- 이동 후보는 점수 내림차순, 사용 이동력 오름차순, 남은 이동력 내림차순,
  Y/X 좌표, 직렬화된 경로, 후보 ID 순으로 정렬한다.
- 스타터는 `bow`, `mascot-costume` 순이고 agent는 위 문서 순서로 실행한다.
- 보고서에는 시각, Git SHA, 환경 경로처럼 실행마다 달라지는 값을 넣지 않는다.
- 한 시나리오가 256개의 모델 변경 명령을 사용하면 `command-limit`로 즉시 종료해
  무한 루프를 막는다. CLI로 조정할 수 있지만 추적 메모리 보호를 위해 허용 범위는
  1~4096회로 제한한다.

## 수집 지표

- 모델 완료, 플레이어 패배, 턴 제한, 명령 제한, 불변식 실패 종료 분류
- 모델 outcome/reason과 엔딩 ID
- 최종 플레이어·로라 HP, 불안정도, 층, 로라 행동 횟수
- 시작·획득·사용·잔여 아이템과 고유 사용 아이템 ID
- 층별 로라/몹에게 준 피해와 플레이어가 받은 피해
- 공격, 회복, 대기, 아이템 사용, 정화, 이동 횟수
- 이동·플레이어 행동·로라 행동 preview와 같은 명령의 실제 투영 불일치
- 명령 수, 명령 종류와 간결한 결정 추적

## 실행과 판정

테스트·시뮬레이션 재개 승인을 받은 뒤 저장소 루트에서 다음을 실행한다.

```bash
npm run simulate:balance
npm run test:balance
```

보고서만 표준 출력에 내보내고 파일을 만들지 않으려면 다음을 사용한다.

```bash
npm run simulate:balance -- --json --no-write
```

기준선 확정 시 이 문서의 ‘실행 결과 기준선’을 실제 집계값으로 교체한다.
하네스 구조 실패나 preview 불일치가 하나라도 있으면 CLI는 실패 종료 코드를
설정한다. 모델의 성공·패배·턴 제한은 관찰 대상 결과이며 그 자체가 하네스
오류는 아니다.

## 해석 한계

- agent는 현재 snapshot과 preview만 보고 미래 로라·몹 행동을 탐색하지 않는다.
- 이동은 한 턴의 `getReachability()` 후보만 비교하며 전역 경로를 계획하지 않는다.
- UI 연출, 입력 숙련도, 탐색 호기심과 서사적 선택은 측정하지 않는다.
- 네 휴리스틱의 결과는 최적 플레이나 실제 플레이어 승률이 아니다.
