# N번째 플레이어 릴리스 후보 보고서

- 작성일: 2026-08-28 (Asia/Seoul)
- 대상: `main`, 이 문서를 포함하는 Figma UI 정합화 커밋
- 후보 런타임: NW.js `0.108.0` Windows x64
- 판정: **내부 RC 검증 통과 / 공개 릴리스 차단**

## 1. 결론

16턴 구현 범위의 모델, 두 층 전투, 비전투 화면, 컷씬·갤러리, 실제 아트·오디오,
스프라이트 연출, 메타 저장, CI, 정적 감사와 Windows 패키징 계약을 한 `main` 코드베이스로
통합했다. 전체 Node 테스트와 정적 검사는 통과했고, NW.js 수동 스모크에서 메뉴·갤러리·컷씬,
두 스타터 진입과 첫 로라 행동 뒤 게이지 표시를 확인했다.

그러나 코드의 공개 배포 라이선스와 제공 아트·오디오의 원본별 권리 증빙이 없으며,
Minecraft·Mario·The Legend of Zelda·MapleStory를 직접 참조한 아이템 표현이 포함돼 있다.
따라서 이 후보는 내부 검증·데모 용도로만 승인하며, 권리 확인 또는 대체 에셋 적용 전 공개
배포를 금지한다.

## 2. Turn 16에서 강화한 경계

- 메타 저장을 v4로 올리고 v1→v2→v3→v4 순차 이관을 명시했다.
- `discoveredTrapIds`를 현재 기획 용어인 `revealedEventTileIds`로 이관하고 저장 시 구 키를
  제거한다. v2 `bestScore`는 읽기 호환만 유지한다.
- 현재 빌드보다 새로운 메타 버전은 읽기·저장을 거부한다. 장면은 기본 메타로 계속 실행하되
  해당 실행의 메타 쓰기를 막아 미래 저장을 덮어쓰지 않는다.
- 손상·부분 메타는 타입, 음수, 중복 ID와 누락 필드를 방어 정규화한다.
- 공식 `nwjs-v0.108.0-win-x64`만 받는 검증기와 allowlist 패키저를 파일당 한 클래스로 분리했다.
- import map을 포함한 정적 그래프, 미해결 import, 순환, 런타임 에셋 경로, TODO/FIXME,
  `debugger`, UNDO 잔존, 출처 누락을 `check:release`가 검사한다.
- display/theme 순환을 끊기 위해 배경색 쓰기 경계를 `_display_background_port.js`로 분리했다.
- 메타 schema/migrator/version error/storage operation, 패키징 contract/validator/packager,
  세 릴리스 auditor를 각각 독립 파일과 단일 책임으로 구성했다.

## 4. 수동 NW.js 스모크

- 실행 파일 제품 버전: `0.108.0`
- 창 크기: 1538×900
- 확인 완료: 메인 메뉴, 완료 횟수, 점수 UI 제거, 다섯 갤러리 섹션, 잠금·책·책갈피,
  오프닝 재생·스킵·갤러리 복귀, 활·인형탈 스타터 화면과 각각의 전투 진입, 메뉴 복귀.
- Turn 16 추가 확인: 활 전투에서 제자리 이동 확정→대기→첫 로라 전체 공격 뒤 플레이어 HP가
  `100→75`, 로라 불안정도가 `70→73`으로 화면과 행동 미리보기에 일치했다.
- 첫 시도에서 HP·불안정도 cue의 숫자 `from/to`가 좌표 정규화에 의해 `null`이 되는 결함을
  발견했다. 타입 보존 수정과 프레젠터→타임라인 회귀 테스트 추가 후 새 격리 인스턴스에서
  재현 절차를 통과했다.
- 메뉴 복귀 뒤 실제 `runtime_state.dat`가 v4와 `revealedEventTileIds`로 저장됨을 확인했다.

합성 키보드 입력은 자동화 도구에서 게임 입력으로 전달됐다는 화면 증거를 얻지 못했다.
장시간 6번째 로라 행동 층 전환과 12회 결과까지의 실제 수동 완주는 이번 Turn 16에서 반복하지
않았으며, 자동 모델·표현 계약으로 검증했다. 실제 공식 NW.js 압축본을 입력으로 한 최종 배포
폴더 조립·실행도 권리 차단 해소 뒤 릴리스 담당자가 수행해야 한다.

## 5. 패키징 재현성과 안전 정책

`npm run package:nwjs`는 다음 조건을 모두 만족해야 실행된다.

1. 입력 폴더 이름이 `nwjs-v0.108.0-win-x64`이다.
2. `nw.exe` 제품 버전과 필수 Windows 런타임 파일·디렉터리가 계약과 일치한다.
3. 출력 폴더가 아직 존재하지 않는다.
4. 패키지는 `engine`, `asset/tutorial`, 온글잎 박다현체 폰트, 앱 아이콘, 런타임
   `package.json`, `license`, `THIRD_PARTY_NOTICES.md`만 복사한다.
5. `nw.exe`는 `nth-player.exe`로 바꾸고 NW.js `credits.html`과 결정론적
   `BUILD_INFO.json`을 보존한다.

원본 작업 아트·오디오 디렉터리, `project/save`, 루트 개발 스크립트와 테스트는 결과물에
포함하지 않는다. macOS/Linux는 실행 파일명·번들 구조·제품 버전 검증 계약이 없으므로 지원하지
않는다. 지원 확대 시 운영체제별 공식 NW.js archive, 검증기, allowlist, 실제 실행 스모크를
별도로 추가해야 한다.

## 7. 기획 문서 밖에서 정한 임의 결정

요구사항이 구체적이지 않은 부분은 작업 중단 없이 다음처럼 보수적으로 정했다.

- 현재 포함 실행 파일의 제품 버전에 맞춰 NW.js `0.108.0` Windows x64를 유일한 패키징
  대상으로 고정했다.
- 재현 가능한 CI 기준은 Node `22.18.0`으로 고정했다. 로컬 최종 검증은 호환되는
  Node `22.19.0`에서도 통과했다.
- 출처·권리 증빙이 없는 에셋과 코드 라이선스는 사용 가능으로 추정하지 않고 공개 릴리스
  차단으로 분류했다.
- 미래 버전 저장은 다운그레이드 추정 이관을 하지 않고 읽기 실패·쓰기 차단 정책을 택했다.
- 실제 운영체제 패키징 증거가 없는 macOS/Linux는 미지원으로 표기했다.
- 기존 `debugMode` 전용 로그는 진단 경로로 판단해 제거하지 않고 감사 경고로 남겼다.

회의록·기획 문서를 추가로 확인하지 않아도 코드·에셋·현재 실행 파일에서 안전한 결정을 내릴
수 있는 범위였다. 위 결정 중 제품·법무 판단이 달라지면 계약과 이 보고서를 함께 갱신해야 한다.

## 9. Figma UI 정합화 후 재검증

Figma 파일 `zoYGZCDsEoMfKkaZstqNfL`의 `<<최종 UI>>` 페이지에 있는 13개 평면 참조를
메타데이터·design context·스크린샷으로 확인하고, 기존 아키텍처 위에서 메뉴, 스타터,
독립 Pause, 전투 HUD, 상황 패널, 튜토리얼, 갤러리와 결과 구도를 정합화했다. 제공 UI

밸런스 8개 시나리오의 구조 실패 0·preview 불일치 0이다. 정적 릴리스 감사는 JS 209개,
import 522개, 에셋 219개를 확인했다. 코드 라이선스, 아트·오디오 provenance, 런타임 복사본,
